# Scoring Stability and Model Eval Spec

## 背景

当前 RSS 评分系统已经从“礼貌打分”调整为更严格的高阈值筛选逻辑，但在真实回测中仍暴露出两个核心问题：

1. **评分漂移**
   同一篇文章在同一模型上重复评分，分数会明显波动。cheap 模型尤为明显，单篇 spread 可达到 1.0 以上。

2. **指令遵循性不稳定**
   同样的 prompt 明确要求：
   - 默认大部分文章落在 3 分左右
   - 4.2+ 极少出现
   - 必须输出 `why_not_higher` 和 `negative_signals`

   但不同模型对这些约束的执行力度不同。有些模型虽然“能打分”，却依旧会对结构完整、数据丰富但缺乏新增价值的文章给出偏高分。

这两个问题不只是影响最终排序，也天然构成了一个很有价值的**模型任务评测维度**。

## 目标

这份 spec 定义两类目标：

1. **产品目标**
   让正式评分结果更稳定、更可复现，减少 cheap 模型的随机漂移对筛选结果的破坏。

2. **评测目标**
   把“评分稳定性”和“指令遵循性”显式收敛为模型评估指标，用于比较：
   - 不同模型
   - 不同 provider
   - 不同 prompt 版本
   - 不同后处理规则

## 设计原则

- **稳定性优先于单次高分辨率**
  单次看起来很聪明，但重复评分不稳定的模型，不适合做自动化筛选主力。

- **指令遵循性优先于语言华丽程度**
  能写很多解释但总在给高分的模型，劣于能稳定执行“默认严格打分”的模型。

- **回测先于主流程接入**
  任何模型切换、prompt 变更、评分规则变更，都应先经过回测。

- **cheap 模型和 sota 模型分工不同**
  cheap 模型负责高性价比粗筛，sota 模型负责关键复判和校准对照。

## 关键指标

### 1. 稳定性指标

对同一批文章，固定模型与 prompt，重复评分 `N` 次（建议 `N=3` 或 `N=5`），统计：

- `average_spread`
  单篇 `max(score) - min(score)` 的平均值

- `max_spread`
  单篇最大漂移幅度

- `score_stddev`
  单篇评分标准差

- `unstable_article_rate`
  漂移超过阈值的文章占比
  建议阈值：
  - `spread > 0.5` 记为轻度不稳定
  - `spread > 1.0` 记为明显不稳定

### 2. 指令遵循性指标

对每次回测结果统计：

- `high_score_rate`
  `score >= 4.2` 的文章占比
  这是高分通胀的第一观察指标

- `why_not_higher_presence_rate`
  是否稳定输出 `why_not_higher`

- `negative_signal_presence_rate`
  是否稳定输出 `negative_signals`

- `strictness_alignment`
  是否符合“默认 3 分附近、高分稀缺”的预期分布

- `cheap_vs_sota_gap`
  相同样本上，cheap 与 sota 的平均分差异
  用于衡量 cheap 模型是否长期偏高

### 3. 业务解释性指标

- `signal_density`
  `negative_signals` 的覆盖程度，避免“只给分不解释”

- `disagreement_article_list`
  cheap 与 sota 分歧最大的文章列表

- `repeat_instability_list`
  同一模型重复评分漂移最大的文章列表

这两个列表应作为人工审阅入口。

## 目标阈值

以下是建议的目标，不是硬编码规则：

### cheap 模型最低可接受线

- `average_spread <= 0.5`
- `max_spread <= 1.0` 的文章占多数
- `high_score_rate` 明显低于旧版评分逻辑
- `why_not_higher_presence_rate >= 95%`
- `negative_signal_presence_rate >= 80%`

### sota 模型目标

- `average_spread <= 0.3`
- `high_score_rate` 更低，且解释更一致
- 对 cheap 高分样本能更稳定地下调

## 正式评分流程的建议改造

### Phase 1: 回测和评测先行

继续使用 `scripts/backtest_scoring.py` 作为主入口，支持：

- 单模型重复回测
- 多模型横向对比
- 输出稳定性指标与分歧文章列表

### Phase 2: 主流程稳定化

在正式评分链路中引入以下策略：

1. **cheap 模型默认重复评分**
   对边界文章或高优文章执行 `repeat=3`

2. **默认使用均值分**
   不再直接使用单次分数，而是使用平均分或中位数

3. **高漂移惩罚**
   若 `spread` 过高，则降低最终排序优先级

4. **sota 复判**
   对进入高优先级的候选，再用 sota 模型复判一次

### Phase 3: 模型选择机制

后续模型切换不再靠体感决定，而是由回测指标驱动：

- 若新 cheap 模型更稳、且对高分通胀控制更好，则替换当前 cheap
- 若新 sota 模型更稳且更符合严格 prompt，则作为复判模型

## 为什么评分任务是高价值模型评测任务

这类评分任务表面上像是“让模型打个分”，但本质上并不低级，反而非常适合拿来区分模型能力层次。

1. **它是裁决任务，不是抽取任务**  
   模型不是在抽标题、日期、关键词，而是在判断“这篇到底值不值得读”“为什么不该更高”。这要求模型做相对复杂的比较、校准和取舍。

2. **它要求稳定的判断标准**  
   真正有价值的不是某一次打分像样，而是同一篇文章多次评分时标准要尽量一致。稳定性本身就是模型能力的一部分。

3. **它要求识别伪高质量信号**  
   很多文章结构完整、数据不少、行业名词密集，但本质只是二次整理、营销包装或浅层扩写。模型能否稳定识别这种“看起来像高质量”的内容，是区分强模型和弱模型的重要能力。

4. **它比很多确定性编码子任务更依赖校准能力**  
   一些编码任务可以通过测试、编译和静态检查给出明确反馈；而评分任务缺少天然标准答案，更考验模型的品味、阈值控制和指令遵循。

因此，这类评分任务不只是业务需求，也可以作为模型评测基准：它能同时衡量稳定性、严格性、解释性和指令遵循性。

## 当前观察结论

基于近期回测，已经能得到一些明确结论：

- `stepfun/step-3.5-flash:free` 漂移偏大，不适合直接用单次结果做精细排序
- `qwen/qwen3.6-plus-preview:free` 相比前者更稳，也更保守，更适合 cheap 档
- 某些所谓 `sota` provider 并不一定真正可用，必须先通过最小 completion 健康检查

因此，“模型可连通性”本身也应被纳入回测前置条件。

## 实施建议

### 短期

- 固定 `temperature=0`
- cheap 模型优先比较稳定性，而不是只比较平均分
- 将 `repeat`、`average_spread`、`largest_spreads` 作为每次回测报告固定输出

### 中期

- 在正式评分流程中接入 `repeat=3 + mean score`
- 对高漂移文章打上 `unstable_score` 标记

### 长期

- 建立一组固定 benchmark 样本集
- 每次 prompt / model / provider 变更都跑同一套回测
- 把结果整理为模型排行榜，而不仅是一次性的实验结论

## 非目标

这份 spec 当前不涉及：

- 重新定义上层 `Process Stream` 的业务分层
- 把所有文章都改成 sota 评分
- 训练自定义评分模型

重点仍然是：**先让现有自动化评分变得稳定、可解释、可评估。**
